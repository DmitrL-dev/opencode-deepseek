## Почему остановилась живая попытка

В исходных последовательных SSE-событиях уже были два соседних APPEND одного
разделителя вместо одного, безымянные закрывающие теги параметров, пропущенные
границы вызовов и открывающий безымянный тег перед концом пакета. Это не результат
склейки или нормализации мостом. Независимая простая сборка наблюдаемого потока
совпала с сохранённым ответом и результатом производственного декодера.
Поток полностью сохранён: EOF присутствует, усечения нет, сервер завершил ответ
со статусом FINISHED. Нормальное завершение транспорта не делает вызовы валидными.

Мост запросил исправленный DSML-формат, но это не гарантирует, что веб-модель
соблюдёт его. Влияние старых неправильных примеров в истории возможно, однако
этой попыткой не доказано. Подменять неверный пакет исполняемыми вызовами нельзя:
для этого пришлось бы додумывать отсутствующие границы. Парсер намеренно не ослаблен.

В `tests/test_dsml_stream_boundary.py` добавлена обезличенная регрессия:
повторяющиеся SSE-фрагменты сохраняются точно, обе реализации API отвергают
неполный пакет целиком, сохраняют диагностику и не вызывают новую генерацию.
Два новых теста прошли офлайн. Предыдущий полный локальный прогон: 848 тестов,
799 пройдены, 49 пропущены. Эта запись не подменяет результаты CI нового коммита.

## Офлайн-разбор JSON-продолжения

Сохранённый второй запрос JSON-прогона восстановлен через настоящий
`ConversationCache.prepare()` на отдельной базе. Digest подготовленного хвоста
совпал с `recovery_binding.request_digest` ошибки. Рабочую базу для этого
не открывали на запись. Данные запроса содержат 30 сообщений и 17 схем;
в существующий диалог отправлялись только сопоставление прошлого вызова
и его новый результат, затем инструкции моста.

Независимая сборка операций APPEND из исходного SSE, без production-парсера,
дала точное совпадение с сохранённым ответом. Поток полный (`eof=true`,
`truncated=false`, `FINISHED`). Лишняя `}` уже находится в ответе провайдера;
после неё отдельным дефектом остаётся параметр `arguments`, которого нет
в схеме `bash`. Исправлять скобку или разворачивать этот параметр нельзя.
Оба валидатора отклоняют весь оригинальный пакет, включая первый `get_goal`.

В сборке исходящего запроса найдены и устранены локальные источники неоднозначности:

- Сопоставление уже выданного вызова с результатом снова оформлялось активным
  `tool_calls`-блоком, включая исторический ID. Теперь это JSON-данные истории
  в обоих режимах; имена, ID и значения аргументов сохраняются точно.
- Образец текущего JSON отделяли от конца запроса 8622 байта дополнительных
  правил. Теперь единый контракт находится после схем и правил выполнения;
  на том же запросе от начала образца до конца 303 байта. Схемы и правила
  безопасности не сокращены. `full`, `medium` и `light` используют один
  генератор контракта; явные `none` и compact-result режимы сохраняют поведение.
- Контракт различает текстовый протокол внешнего исполнителя и native calls,
  JSON-обёртку `arguments` и реальные поля схемы. Образцы прежнего формата
  объявляются неактуальными только для формата ответа, без отмены ограничений
  задачи и наблюдавшихся результатов. XML-подобные placeholder-имена убраны.

Один новый регрессионный набор до исправления воспроизводил два образца вызова
и неверное размещение контракта; после исправления проходит. Проверяется
побайтовое сохранение строк аргументов, привязка результатов, неизменность
digest исходной истории и отказ повторного использования уже потреблённой
ссылки. Парсер, JSON Schema validation, учёт нагрузки, паузы и автоматические
повторы не менялись.

Это доказательство локальных дефектов запроса, а не доказанная причина каждого
решения модели. JSON-проба продолжала прежний серверный диалог с DSML-историей;
смена `.env` её не очищает. Веб-транспорт передаёт текст `prompt`, без native
`tools` или принудительного `response_format`. По сохранённому потоку нельзя
установить внутреннюю причину выбора DSML или обещать соблюдение JSON после
этого изменения. Новых генераций, запросов истории или входов в аккаунт
для этой проверки не было; повреждённый ответ не восстановлен и не выдан.

Итог офлайн-проверки: 869 тестов, 820 пройдены, 49 штатно пропущены.
Первый запуск с полным запретом сети дал 814 успешных тестов, 50 пропусков

## Ремонт окружения и следующее штатное продолжение

По отдельному разрешению оператора в прежний приватный test-venv установлены

Это проверка исходников на macOS, а не квалификация платформы продукта.

В Harness через штатный `goals.edit` добавлена отдельная фактическая заметка
об окружении. Исходное определение цели сохранено как префикс; прежний
результат pytest не заменён. Затем вызван штатный `goals.resume`. До живого
продолжения тот же путь проверен на копии Session с localhost-фикстурой:
один перехваченный запрос, ноль запросов провайдеру, исходная Session неизменна.
На копии базы точная история привязалась к принятому ответу со счётчиком 5;
повторное потребление той же связи было отклонено.

Для ограниченного живого прогона включён `TOOLCALL_LOG=1`: приватные файлы
в игнорируемом `logs/` имеют права 0600, каталог 0700. Это расширяет локальный
состав диагностики до запросов и ответов; публиковать эти файлы нельзя.
Перезапуск моста сохранил историю, состояние пауз, счётчики и сессию аккаунта.

Обычное продолжение отправило **две генерации / четыре HTTP-запроса**,
не создало ни одного чата. Первый ответ пришёл как JSON `tool_calls`;
его единственный `bash` успешно просмотрел точки входа owner report.
Тесты и предыдущие команды модель не повторила. Следующий ответ пришёл
в DSML: `bash` получил единственный параметр `arguments` с JSON-объектом
вместо объявленных параметров `description` и `command`; за ним шёл
валидный `read`.

Полный исходный SSE сохранён, `eof=true`, `truncated=false`, статус `FINISHED`.
Независимая сборка операций APPEND совпала с диагностикой. DSML-декодер
точно сохранил вложенный объект; проблема не в JSON-синтаксисе или склейке
потока. Этот объект сам по себе удовлетворяет схеме `bash`, но наружная
структура ей не соответствует. Это не разрешение автоматически разворачивать
параметры: текущий контракт требует явных полей, и обе реализации API
отклоняют весь пакет, включая корректный `read`. В регрессии проверены
`kind=schema`, `tool=bash`, сохранение исходного ответа и отсутствие новой
генерации. Все три теста модуля прошли офлайн; production-парсер не менялся.

Установленная причина данного отказа — несоответствие формы вызова
объявленной схеме. Причина, по которой модель сменила формат между двумя
соседними ответами, по клиентскому потоку не установлена. Первое соблюдение
JSON-контракта не подтверждает его устойчивое соблюдение. Причины прежних
ограничений аккаунта этим прогоном также не устанавливаются.

Сохранность проверена отдельно: все ранее потреблённые строки из 459 исходных
сохранились побайтно; единственная доступная родительская связь потреблена
штатно. Добавлена одна связь со счётчиком 6, затем потреблена для второго
запроса. Ни одна связь не освобождалась для повтора. Все три Session-файла
сохранили старые байты точным префиксом. Журнал нагрузки — прежний журнал
плюс ровно четыре записи, без сброса или удаления. Аккаунт и другие
защищённые файлы неизменны. Цель active/disarmed, revision=8; новых запросов
после ошибки нет. Длительная цель и итоговый отчёт Рентгена не завершены.
