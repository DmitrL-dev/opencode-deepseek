# Проверка продолжения цели — 23 октября 2026

Проверяемый мост: `dc52b05d2063a9474a7c8fc2cf77935936578265`.
Harness: установленный `0.2.1-rc.2`; его приложение не изменялось.
Все проверки выполнены одним оператором, без субагентов. Сырые ответы,
сессии, профили с токенами и журнал работы сохранены приватно, вне Git.

## Что доказано

| Проверка | Наблюдение | Вывод |
| --- | --- | --- |
| Обычное продолжение сохранённой цели через headless, локальный провайдер | Один запрос, код `0`, цель не завершена | Выход CLI не доказывает завершение цели |
| Штатный resume перед шагом, прежний headless | Цель активирована, следующий ход начинается перед выходом процесса | У однократного драйвера есть разрыв ожидания продолжения |
| Отдельный проверочный драйвер, штатные сервисы целей | Два автоматических раунда, четыре локальных ответа, реальные `get_goal` и `update_goal`, состояние `complete` | Штатное продолжение работает при ожидании терминального состояния цели |
| Локальный HTTP 400 | Один запрос; цель остаётся `active`, активация `disarmed`; повторов нет | Ошибка останавливает проверку |
| Лимит одного шага проверочного драйвера | Один запрос; второй заблокирован до отправки | Ограничение реально действует |
| Возобновление по точной истории | Новый запрос на копии кеша привязался к сохранённому ответу; исходная база не менялась | Привязка не требует сброса истории |
| Одна живая попытка через рабочий мост | Одна генерация, два HTTP-запроса, ноль новых чатов, ноль выполненных инструментов | Шаг остановлен на неверной разметке |

В офлайн-прогонах внешний сетевой доступ был запрещён ОС; ответы давал локальный
сервер. Каждый прогон использовал отдельную копию Harness Session. Ошибки самого
проверочного драйвера были исправлены и повторно проверены на копиях до живой
попытки: изменение цели внутри уведомления append было перенесено в допустимую
точку жизненного цикла; завершение проверяется по фактическому `phase=complete`.
Ни один из этих тестов не завершал настоящую пользовательскую цель.

## Почему остановилась живая попытка

В исходных последовательных SSE-событиях уже были два соседних APPEND одного
разделителя вместо одного, безымянные закрывающие теги параметров, пропущенные
границы вызовов и открывающий безымянный тег перед концом пакета. Это не результат
склейки или нормализации мостом. Независимая простая сборка наблюдаемого потока
совпала с сохранённым ответом и результатом производственного декодера.
Поток полностью сохранён: EOF присутствует, усечения нет, сервер завершил ответ
со статусом FINISHED. Нормальное завершение транспорта не делает вызовы валидными.

Мост запросил исправленный DSML-формат, но это не гарантирует, что веб-модель
соблюдёт его. Влияние старых неправильных примеров в истории возможно, однако
этой попыткой не доказано. Подменять неверный пакет исполняемыми вызовами нельзя:
для этого пришлось бы додумывать отсутствующие границы. Парсер намеренно не ослаблен.

В `tests/test_dsml_stream_boundary.py` добавлена обезличенная регрессия:
повторяющиеся SSE-фрагменты сохраняются точно, обе реализации API отвергают
неполный пакет целиком, сохраняют диагностику и не вызывают новую генерацию.
Два новых теста прошли офлайн. Предыдущий полный локальный прогон: 848 тестов,
799 пройдены, 49 пропущены. Эта запись не подменяет результаты CI нового коммита.

## Сохранность и ограничения

- Все 451 исходная строка истории остались неизменными. В текущей базе 454 строки;
  единственное изменение живой попытки — потребление разрешённой родительской
  связи и её claim-token. Неиспользованные связи не освобождались для повторов.
- Общие счётчики не сбрасывались; новая попытка учтена. История Harness дополнена
  реальным исходом, ранее выполненные команды не повторялись.
- Новых запросов после ошибки не было. Ошибка относится к формату ответа;
  подтверждения блокировки аккаунта в этом потоке нет. Состояние сайта отдельно
  не проверялось, поэтому отсутствие блокировки аккаунта не гарантируется.
- Длительная задача по Рентгену не завершена: реальное чтение, изменение файлов,
  тесты проекта и итоговый отчёт этим прогоном не подтверждены.
- Полная надёжность веб-эмуляции tool calls и отсутствие будущих ограничений
  провайдера остаются неподтверждёнными. Зелёный CI не заменяет такую проверку.
