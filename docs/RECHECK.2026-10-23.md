# Проверка продолжения цели — 23 октября 2026

Проверяемый мост: `dc52b05d2063a9474a7c8fc2cf77935936578265`.
Harness: установленный `0.2.1-rc.2`; его приложение не изменялось.
Все проверки выполнены одним оператором, без субагентов. Сырые ответы,
сессии, профили с токенами и журнал работы сохранены приватно, вне Git.

## Что доказано

| Проверка | Наблюдение | Вывод |
| --- | --- | --- |
| Обычное продолжение сохранённой цели через headless, локальный провайдер | Один запрос, код `0`, цель не завершена | Выход CLI не доказывает завершение цели |
| Штатный resume перед шагом, прежний headless | Цель активирована, следующий ход начинается перед выходом процесса | У однократного драйвера есть разрыв ожидания продолжения |
| Отдельный проверочный драйвер, штатные сервисы целей | Два автоматических раунда, четыре локальных ответа, реальные `get_goal` и `update_goal`, состояние `complete` | Штатное продолжение работает при ожидании терминального состояния цели |
| Локальный HTTP 400 | Один запрос; цель остаётся `active`, активация `disarmed`; повторов нет | Ошибка останавливает проверку |
| Лимит одного шага проверочного драйвера | Один запрос; второй заблокирован до отправки | Ограничение реально действует |
| Возобновление по точной истории | Новый запрос на копии кеша привязался к сохранённому ответу; исходная база не менялась | Привязка не требует сброса истории |
| Одна живая попытка через рабочий мост | Одна генерация, два HTTP-запроса, ноль новых чатов, ноль выполненных инструментов | Шаг остановлен на неверной разметке |

В офлайн-прогонах внешний сетевой доступ был запрещён ОС; ответы давал локальный
сервер. Каждый прогон использовал отдельную копию Harness Session. Ошибки самого
проверочного драйвера были исправлены и повторно проверены на копиях до живой
попытки: изменение цели внутри уведомления append было перенесено в допустимую
точку жизненного цикла; завершение проверяется по фактическому `phase=complete`.
Ни один из этих тестов не завершал настоящую пользовательскую цель.

## Почему остановилась живая попытка

В исходных последовательных SSE-событиях уже были два соседних APPEND одного
разделителя вместо одного, безымянные закрывающие теги параметров, пропущенные
границы вызовов и открывающий безымянный тег перед концом пакета. Это не результат
склейки или нормализации мостом. Независимая простая сборка наблюдаемого потока
совпала с сохранённым ответом и результатом производственного декодера.
Поток полностью сохранён: EOF присутствует, усечения нет, сервер завершил ответ
со статусом FINISHED. Нормальное завершение транспорта не делает вызовы валидными.

Мост запросил исправленный DSML-формат, но это не гарантирует, что веб-модель
соблюдёт его. Влияние старых неправильных примеров в истории возможно, однако
этой попыткой не доказано. Подменять неверный пакет исполняемыми вызовами нельзя:
для этого пришлось бы додумывать отсутствующие границы. Парсер намеренно не ослаблен.

В `tests/test_dsml_stream_boundary.py` добавлена обезличенная регрессия:
повторяющиеся SSE-фрагменты сохраняются точно, обе реализации API отвергают
неполный пакет целиком, сохраняют диагностику и не вызывают новую генерацию.
Два новых теста прошли офлайн. Предыдущий полный локальный прогон: 848 тестов,
799 пройдены, 49 пропущены. Эта запись не подменяет результаты CI нового коммита.

## Сохранность и ограничения

- Все 451 исходная строка истории остались неизменными. В текущей базе 454 строки;
  единственное изменение живой попытки — потребление разрешённой родительской
  связи и её claim-token. Неиспользованные связи не освобождались для повторов.
- Общие счётчики не сбрасывались; новая попытка учтена. История Harness дополнена
  реальным исходом, ранее выполненные команды не повторялись.
- Новых запросов после ошибки не было. Ошибка относится к формату ответа;
  подтверждения блокировки аккаунта в этом потоке нет. Состояние сайта отдельно
  не проверялось, поэтому отсутствие блокировки аккаунта не гарантируется.
- Длительная задача по Рентгену не завершена: реальное чтение, изменение файлов,
  тесты проекта и итоговый отчёт этим прогоном не подтверждены.
- Полная надёжность веб-эмуляции tool calls и отсутствие будущих ограничений
  провайдера остаются неподтверждёнными. Зелёный CI не заменяет такую проверку.

## English summary

Native goal continuation completed two offline rounds when the verification driver
waited for the goal's terminal state. The installed one-shot headless runner can
exit before queued goal work finishes. The one live bridge attempt still returned
malformed DSML, already present in the raw SSE. No tools executed, no generation
was retried, no new provider chat was created, and history/counters were preserved.
The long real task and reliable web tool emulation remain unverified.

После исходной остановки оператор продолжил проверку в той же Harness Session.
Добавлен явный `DEEPSEEK_TOOL_THINKING`: выбор Expert и DeepThink — разные оси;
изначально клиент не передавал `thinking`. Настройка меняет только транспортный
флаг, не ключи истории, схемы, бюджеты или политику повторов.

1. Один новый диалог получил точный архив задачи, инструкции и наблюдавшиеся
   результаты. Последние заметки ассистента переданы ссылками на архив, чтобы
   повреждённая разметка не была примером. Ответ имел все закрывающие теги, но
   смешивал два известных симметричных написания маркеров. Сырой SSE совпал
   с сохранённым текстом. Разбор этих лексических вариантов исправлен на границах
   тегов; значения параметров не переписываются и пропущенные теги не достраиваются.
2. Ответ восстановлен без генерации. Затем два обычных продолжения прошли:
   всего шесть инструментов выполнились успешно. Следующий пакет содержал
   оборванное начало параметра и асимметричные разделители. Он целиком отклонён.
   Все 454 ранее существовавшие строки кеша остались неизменны, добавлены три
   новые связи. Выполненные действия не повторялись.
3. После отдельного явного разрешения пользователя выполнена **одна** повторная
   генерация с запросом JSON, от последнего ответа того же диалога. Нового чата
   не создавали; счётчик принятых ответов продолжен с 3 до 4. Этот шаг выполнил
   ещё одну команду. Следующий обычный шаг вернул DSML с JSON-значением, содержащим
   лишнюю закрывающую скобку, и не предусмотренной схемой обёрткой `arguments`.
   Весь пакет, включая корректный первый `get_goal`, отклонён. Повторов нет.
   Сохранённый сырой поток совпал с диагностикой и подтвердил `thinking_enabled=true`.

Эти наблюдения опровергают достаточность исправления примера, чистого контекста,
DeepThink или переключения на JSON для надёжности этой веб-модели. Они не
устанавливают причину прежних блокировок аккаунта. Проверки схем и запрет
автоматического воспроизведения не ослаблены. Полноценная длительная задача
остаётся незавершённой; семь успешных инструментов — ограниченный результат,
а не подтверждение полного автономного комплекта.

Выявлен отдельный предел диагностики: четыре сохранённых потока заполнили каталог.
Текст второго сбоя и точный ID остались в диагностике, но сырые байты не сохранились.
Добавлены явный `stream_capture_status`, локальный статус вместимости и настройка
`DEEPSEEK_STREAM_CAPTURE_FILES` (1–32, по умолчанию 4). На проверяемой установке
вместимость поднята до 16; старые файлы не удалялись. Следующий сбой сохранён полностью.
Оба README различают офлайн-проверки и фактический ограниченный живой результат.

## Офлайн-разбор JSON-продолжения

Сохранённый второй запрос JSON-прогона восстановлен через настоящий
`ConversationCache.prepare()` на отдельной базе. Digest подготовленного хвоста
совпал с `recovery_binding.request_digest` ошибки. Рабочую базу для этого
не открывали на запись. Данные запроса содержат 30 сообщений и 17 схем;
в существующий диалог отправлялись только сопоставление прошлого вызова
и его новый результат, затем инструкции моста.

Независимая сборка операций APPEND из исходного SSE, без production-парсера,
дала точное совпадение с сохранённым ответом. Поток полный (`eof=true`,
`truncated=false`, `FINISHED`). Лишняя `}` уже находится в ответе провайдера;
после неё отдельным дефектом остаётся параметр `arguments`, которого нет
в схеме `bash`. Исправлять скобку или разворачивать этот параметр нельзя.
Оба валидатора отклоняют весь оригинальный пакет, включая первый `get_goal`.

В сборке исходящего запроса найдены и устранены локальные источники неоднозначности:

- Сопоставление уже выданного вызова с результатом снова оформлялось активным
  `tool_calls`-блоком, включая исторический ID. Теперь это JSON-данные истории
  в обоих режимах; имена, ID и значения аргументов сохраняются точно.
- Образец текущего JSON отделяли от конца запроса 8622 байта дополнительных
  правил. Теперь единый контракт находится после схем и правил выполнения;
  на том же запросе от начала образца до конца 303 байта. Схемы и правила
  безопасности не сокращены. `full`, `medium` и `light` используют один
  генератор контракта; явные `none` и compact-result режимы сохраняют поведение.
- Контракт различает текстовый протокол внешнего исполнителя и native calls,
  JSON-обёртку `arguments` и реальные поля схемы. Образцы прежнего формата
  объявляются неактуальными только для формата ответа, без отмены ограничений
  задачи и наблюдавшихся результатов. XML-подобные placeholder-имена убраны.

Один новый регрессионный набор до исправления воспроизводил два образца вызова
и неверное размещение контракта; после исправления проходит. Проверяется
побайтовое сохранение строк аргументов, привязка результатов, неизменность
digest исходной истории и отказ повторного использования уже потреблённой
ссылки. Парсер, JSON Schema validation, учёт нагрузки, паузы и автоматические
повторы не менялись.

Это доказательство локальных дефектов запроса, а не доказанная причина каждого
решения модели. JSON-проба продолжала прежний серверный диалог с DSML-историей;
смена `.env` её не очищает. Веб-транспорт передаёт текст `prompt`, без native
`tools` или принудительного `response_format`. По сохранённому потоку нельзя
установить внутреннюю причину выбора DSML или обещать соблюдение JSON после
этого изменения. Новых генераций, запросов истории или входов в аккаунт
для этой проверки не было; повреждённый ответ не восстановлен и не выдан.
